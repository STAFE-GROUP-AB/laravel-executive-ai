## 1. On disk

```
~/Library/Application Support/<bundle id>/
  runtime/
    <version>/              immutable: chmod -R a-w after the rename, before `current` is flipped
      frankenphp            the signed FrankenPHP binary (ADR-001 D2)
      Caddyfile             static, loopback only; port and root come from the environment (§3)
      php.ini               static: opcache on, opcache.jit=disable, pcre.jit=1, validate_timestamps=0
      app/                  the Laravel tree: composer --no-dev, bootstrap/cache/{packages,services}.php
      manifest.json         schema 1, generated by assemble-runtime.mjs = runtime.json#package
      SHA256SUMS            sha256sum format, same digests as manifest.json
    current -> <version>    symlink, switched with rename(2) — atomic
    previous -> <version>   the version rolled back to by RuntimeInstalling.rollbackToPrevious(in:)
  data/                     mutable, user-owned
    database/               executive.sqlite (+ -wal, -shm)      ← Time Machine excluded (§4)
    storage/app/{private,public}
    storage/framework/{cache/data,sessions,views}                 ← Time Machine excluded (§4)
    storage/logs -> ~/Library/Logs/<bundle id>                    symlink
    backups/                verified VACUUM INTO snapshots (ADR-002 D5) — inside Time Machine
  install/checkpoint.json   installer bookkeeping (installer.md §3)
~/Library/Logs/<bundle id>/      install events, Supervisor and runtime logs; never backed up
~/Library/Caches/<bundle id>/    may be lost at any time; never backed up
```

`<bundle id>` is `LXAI_BUNDLE_PREFIX` + `.app` from `apps/macos/Config/Shared.xcconfig`
(`se.stafe.executive-ai.app` until A12 settles). ADR-001 D4 writes the directory as
`LaravelExecutiveAI`; the code uses the bundle id, as installer.md §8 already notes. One of the two
changes when A12 is decided, nothing else does.

Rules the installer enforces (`RuntimeInstaller`, tested):

- **Nothing in `runtime/<version>/` is written after install.** The re-hashed staging directory is
  renamed to `runtime/<version>/` with `rename(2)`, every file and directory then loses its write
  bits in place (`chmod -R a-w`), and only after that is `current` flipped — so no writable tree
  is ever the active runtime. (The order matters: macOS 15's `FileManager` refuses to move a
  directory that is already read-only; macOS 26 does not.) `PackageVerifier.verify(runtimeDirectory:)`
  accepts the installed directory unchanged — that is the check the Supervisor runs on every boot
  (ADR-001 D3), with no special case.
- **Nothing per-machine is inside the runtime.** The Caddyfile reads `{$LEA_HTTP_PORT}` and
  `{$LEA_RUNTIME_DIR}`; php.ini has no path. So the directory is byte-for-byte what
  `runtime.json#package` pins, on every Mac, and "installation fails closed on a mismatch" needs no
  template exception. (S1-05's hand-off suggested rendering the port into the Caddyfile at install
  time; that would have forced either a rewritten `SHA256SUMS` per machine or a "generated file"
  carve-out in the verifier. ADR-001 D4 already says non-secret configuration is process
  environment, so that is what the port is.)
- **Two versions coexist.** Installing `0.2.0` beside `0.1.0` leaves `0.1.0` intact, points
  `current` at `0.2.0` and `previous` at `0.1.0`. Versions older than `previous` are
  garbage-collected after activation. A dangling `previous` is removed, never followed.
- **Rollback** (`rollbackToPrevious(in:)`) flips `current` to `previous` and `previous` to the
  version rolled back from, so a roll-forward is the same call. It refuses when there is no
  previous directory with a `manifest.json`. `data/` is untouched; an incompatible schema change
  is not undone (§9).
- **Data-preserving reinstall.** Installing the version `current` already points at replaces the
  runtime directory and leaves `data/` byte-identical (tested on the SQLite file). `previous` is
  not touched.
- **Uninstall** (`RuntimeUninstaller.remove(preservingData:includingInstallDirectory:in:)`)
  removes `runtime/`, `run/`, Caches and Logs, and `install/` unless the caller keeps it; keeps or
  removes `data/`. When data is preserved, the `storage/logs` symlink is replaced by an empty real
  directory so the preserved tree is self-contained; a later install re-links it. Idempotent.
  This is step 4 of the S1-13 order (services.md §8): the UI, the launchd unregistration, the
  Keychain sweep through the Supervisor, the reinstall marker and the Trash step are
  `Install/Uninstaller.swift`, documented in
  [`docs/operations/uninstall.md`](../operations/uninstall.md).

## 2. Laravel side

`bootstrap/app.php` calls `RuntimeLayout::apply($app)` after `create()`. With `LEA_DATA_DIR` set
to an absolute path:

| Helper | Resolves to |
|---|---|
| `base_path()` | the runtime's `app/` (derived from the file system, unchanged) |
| `storage_path()` | `<LEA_DATA_DIR>/storage` |
| `database_path()` | `<LEA_DATA_DIR>/database` |
| `config('database.connections.sqlite.database')` default | `<LEA_DATA_DIR>/database/executive.sqlite` |
| migrations | `base_path('database/migrations')`, registered by `AppServiceProvider` because `database_path()` no longer points at them |

A relative or empty `LEA_DATA_DIR` is ignored (nothing may silently land inside the runtime);
without the variable (development, tests, the `server` profile) every path is Laravel's default.
`config:cache`, `route:cache` and `event:cache` are **not** part of the runtime: the assembler
refuses `bootstrap/cache/{config,routes-v7,events}.php` because a config cache freezes environment
values at build time (ADR-003) and `storage_path()` would be baked in. Only
`bootstrap/cache/{packages,services}.php` (package discovery) ship.

## 3. Environment the Supervisor passes (S1-07 contract)

`RuntimeEnvironment.supervisorEnvironment(runtime:paths:port:)` in `RuntimeInstaller.swift` is the
reference. Every PHP child (HTTP, `queue:work`, `schedule:work`) gets exactly:

| Variable | Value | Read by |
|---|---|---|
| `LEA_RUNTIME_DIR` | `…/runtime/<version>` (the resolved directory, not the `current` link) | Caddyfile `root`; `config/ipc.php` (`basename` → `runtime_version` in the heartbeat response, ipc-contract §6.5) |
| `LEA_DATA_DIR` | `…/data` | `RuntimeLayout` (§2) |
| `LEA_CACHE_DIR` | `~/Library/Caches/<bundle id>` | reserved for GUI/Supervisor caches |
| `LEA_LOG_DIR` | `~/Library/Logs/<bundle id>` | Supervisor stdout/stderr capture |
| `LEA_HTTP_PORT` | the port preflight recorded in `install/checkpoint.json` (`preflight.port`) | Caddyfile `http://127.0.0.1:{$LEA_HTTP_PORT}`; `config/ipc.php` (`Host` must be exactly `127.0.0.1:<port>` on `/ipc/*` and `/health/ready`, and `X-Lxai-Origin` echoes it — ipc-contract §5.2, §4.5) |
| `PHPRC` | `…/runtime/<version>` — the directory holding `php.ini` | PHP |
| `APP_ENV` / `APP_DEBUG` | `production` / `false` | Laravel |
| `APP_URL` | `http://127.0.0.1:<port>` | Laravel |
| `LEA_BACKEND_PROFILE` | `local` | `config/lea.php` |
| `LEA_SECRETS_SOCKET` | `…/Application Support/<bundle id>/run/secrets.sock` — the Supervisor's secrets broker (ADR-003 D3; added by S1-07, `RuntimeEnvironment.secretsSocketKey`) | `config/secrets.php` selects the `supervisor` driver when it is present; `App\Security\Secrets\SupervisorSecretStore` connects to it |

Commands, from ADR-001 D3, with the working directory set to `LEA_RUNTIME_DIR`:
`frankenphp run --config Caddyfile`, `frankenphp php-cli app/artisan queue:work database …`,
`frankenphp php-cli app/artisan schedule:work`. Caddy has no default for the two placeholders on
purpose: a missing variable makes it refuse to start, which the Supervisor reports, instead of
binding somewhere unexpected. **No `APP_KEY`, token or password is ever in this environment**
(ADR-003 D7 row 12; the key reaches PHP through the broker, ADR-003 D5).

## 4. Time Machine (OPEN-QUESTIONS A21)

The data directory's live database is excluded with **`/usr/bin/tmutil addexclusion <path>`**
(item-level, sticky, no privileges), applied by the installer to `data/database/` and
`data/storage/framework/` — not to `data/` as a whole, because `data/backups/` holds the verified
`VACUUM INTO` snapshots that ADR-002 D5 wants Time Machine to copy, and an exclusion cannot be
undone for a subdirectory. `URLResourceKey.isExcludedFromBackupKey` (ADR-003 E26) stays the
mechanism for the GUI's brief cache only. A failed `tmutil` fails the install (threat model T-43:
an unexcluded live copy is exactly what must not accumulate). The real tool is behind
`BackupExcluding`; tests and the DEBUG simulation use `RecordingBackupExclusion`.

## 5. Manifest, packaging, and the runtime in the disk image (S1-12)

`packaging/manifest/runtime.json` (schema `runtime.schema.json`, validated in CI) pins FrankenPHP
1.13.0, PHP 8.5.11 ZTS, Caddy 2.11.7, static-php-cli 2.8.5, the ADR-001 D1 extension list, the
excluded Caddy modules, the signing identity and the loopback port plan
(8787, fallbacks 8788–8799, which support-matrix §6.6 called "placeholder until `runtime.json`
fixes it"). Its `package` member is the directory manifest the installer copies and verifies and its
`artifact` member says where that exact directory is published;
`packaging/runtime/assemble-runtime.mjs` generates both, so they are `null` with `status: unbuilt`
until a real artefact exists. The build recipe, the assembler and the version-bump procedure are in
[`packaging/runtime/README.md`](../../packaging/runtime/README.md).

### The two licence findings, and how A23 closed them

The first real build (2026-10-10) produced a binary that could not be shipped, for two reasons
found by building rather than by reading. **Both are fixed in the recipe** — OPEN-QUESTIONS
**A23**, decided by Andreas on 2026-10-11, no legal-opinion route:

1. **Mercure is linked by FrankenPHP's own `caddy/` module, not only by the xcaddy `--with`
   list.** ADR-001 D1/E4 relied on `SPC_CMD_VAR_FRANKENPHP_XCADDY_MODULES`; with only that, the
   binary still contained `github.com/dunglas/mercure v1.0.3` (AGPL-3.0). The **`nomercure` Go
   build tag** is required, and static-php-cli 2.8.5 hard-codes the tag list with no hook, so
   `build-runtime.sh` patches the pinned spc source (exact-string guarded) and verifies the tag in
   `go version -m`. ADR-001 D1 now names it.
2. **GNU libiconv (LGPL-2.1) was statically linked** because spc 2.8.5 builds `libxml2` — a
   dependency of `php` itself on macOS, and unavoidable since `dom`/`xml`/`simplexml` need it —
   against it; the upstream release artefact has the same. The recipe now builds **libxml2 and the
   `iconv` extension against the macOS system iconv** (ADR-007 D2.2's own prescription): the GNU
   dependency becomes Linux-only in `config/lib.json`/`config/ext.json`, PHP configures
   `--with-iconv` without a buildroot path, and libxml2's CMake gets `Iconv_INCLUDE_DIR` and
   `Iconv_LIBRARY` from the macOS SDK — which it needs, because spc's generated toolchain file sets
   `CMAKE_FIND_ROOT_PATH_MODE_{INCLUDE,LIBRARY} ONLY` against its own buildroot, so
   `find_package(Iconv)` cannot see a system library at all and the configure step fails outright.

**Measured 2026-10-13** (`build-runtime.sh` with both fixes, Apple M4 Max, macOS 26.6.2, Xcode 26.2,
about 16 minutes cold):

| | |
|---|---|
| Binary | `frankenphp`, **145 073 048 bytes** (upstream kitchen-sink release: 180 861 128; the 2026-10-10 libiconv build: 146 227 560) |
| SHA-256 | `eaf81d68af7969382a637155bad52db4fa6c2c96f5fe9f61faafc8f72954da40` |
| Version | `FrankenPHP v1.13.0 PHP 8.5.11 Caddy v2.11.7` |
| Go build tags | `nobadger,nomysql,nopgx,nomercure,nowatcher`; no `dunglas/mercure` or `dunglas/vulcain` dependency line in `go version -m` |
| Linked libraries | `libSystem`, `libresolv`, `libc++`, `libutil`, **`/usr/lib/libiconv.2.dylib`** and the CoreFoundation/CoreServices/SystemConfiguration/Security frameworks — nothing from `/opt/homebrew`, `/usr/local` or `@rpath` |
| Licence gate | **passes with no override** (`LXAI_ALLOW_COPYLEFT_FOR_MEASUREMENT` unset): 12 notice files, **0** with GPL/LGPL/AGPL text, **no libiconv notice**, and no `libiconv.a`/`libcharset.a` in the build tree |
| Runtime facts | 41 extensions, `ZEND_THREAD_SAFE`, SQLite 3.45.2 with FTS5, `pcre.jit=1`, OPcache JIT off |

The iconv entry in that list is the macOS system library: dynamically linked, provided by the OS,
never redistributed by us. Encoding behaviour was verified on the artefact — UTF-8 ↔ ISO-8859-1 and
Windows-1252 round-trip, and libxml2 decodes `encoding="ISO-8859-1"` and `encoding="SHIFT_JIS"`
documents correctly. One behavioural difference from GNU libiconv is recorded in ADR-007 D2.2:
macOS reports `ICONV_IMPL=libiconv, ICONV_VERSION=1.11` and its `//TRANSLIT` output is weaker, so
nothing may depend on `//TRANSLIT`.

This binary was built on a developer Mac and is **proof, not product**: no Developer ID identity
exists outside CI, so it is never signed, never assembled with `--status signed` and never shipped.

### How the directory reaches a user's Mac (S1-12)

Three stages, so that the signed binary's digest is always the one `runtime.json` records:

1. **`.github/workflows/build-runtime.yml`** (dispatch only, `macos-15`) runs the recipe above,
   signs `frankenphp` (Developer ID, hardened runtime, exactly `com.apple.security.cs.allow-jit`),
   assembles `runtime/<version>/` with `--status signed` so `manifest.json` and `SHA256SUMS` hash
   the **signed** bytes, packs it as a tarball, verifies the unpacked copy with the installer's own
   rules, and publishes it on a pre-release tag `runtime-<php>-<frankenphp>-<n>`. CI cannot do this
   per build — it is tens of minutes — which is why it is a separate, manually triggered workflow.
2. **`packaging/manifest/runtime.json`** records the result: `status: signed`, `built_at`,
   `source_commit`, `package` (the directory manifest) and `artifact` (the asset's tag, name, URL,
   size and sha256). The workflow produces it and attaches it to the release; a human commits it.
3. **`.github/workflows/build-macos.yml`** downloads that asset, checks the sha256 and the byte
   count, unpacks it into `Contents/Resources/runtime/`, re-verifies it with the manifest rules and
   refuses a binary whose Team ID is not the app's — all **before** `sign.sh app` runs, so the app's
   resource envelope seals an already-signed runtime and nothing in the directory is signed twice.
   Until an artifact is pinned the step skips with a notice and the image is app + Supervisor only,
   in which case the installer stops at `PACKAGE_VERIFY` (`installer.md` §3).
